# Polymarket 策略验证、回测与上线阶段门

> 版本日期：2026-07-22  
> 适用范围：AI 概率策略、新闻策略、复制交易、套利、体育价值、临近结算和做市  
> 默认原则：未通过本文件定义的阶段门，策略不得扩大真实资金权限。

## 1. 目标与非目标

本规范用于回答三个问题：

1. 策略是否在看不见的数据上表现出可重复的净优势？
2. 该优势在真实费用、流动性、延迟、部分成交和失败场景下是否仍存在？
3. 系统能否在错误发生时限制损失、恢复状态并留下完整审计记录？

本规范不用于：

- 承诺未来胜率或收益；
- 用单次回测替代实盘验证；
- 用模型置信度替代风险限制；
- 用高命中率掩盖赔率不对称和尾部亏损。

## 2. “胜率”必须被拆分

报告中不得只展示一个“胜率”。至少区分：

| 指标 | 定义 | 常见误导 |
|---|---|---|
| 方向准确率 | 预测最终结果正确的比例 | 大量买入 95% 热门结果可获得高准确率，但一次失败可能抹去多次盈利 |
| 交易胜率 | 扣除费用后盈利交易数 / 已关闭交易数 | 可被止盈/止损比例和持仓拆分方式操纵 |
| 成交率 | 成交数量 / 下单数量 | 不是盈利能力；maker 低成交率可能只是报价离市场过远 |
| 结算命中率 | 持有到结算的仓位中获胜比例 | 忽略买入价格，不能代表期望值 |
| 概率校准 | 预测为 70% 的事件是否约有 70% 发生 | 比单纯准确率更适合概率市场 |

任何对外展示的历史胜率必须同时展示：

- 样本数；
- 起止日期；
- 市场类别与持有周期；
- 置信区间；
- 扣费后净收益；
- 最大回撤；
- 是否样本外；
- 是否真实成交或模拟成交。

## 3. 核心经济指标

### 3.1 单边持有到结算

买入 YES 的每股基础净优势：

edge_net = p_hat − executable_ask − taker_fee − slippage − latency_buffer

其中：

- p_hat：模型对 YES 的校准后概率；
- executable_ask：目标数量加权平均可成交 ask，不是 midpoint；
- taker_fee：按该市场当前 fee curve 估算；
- slippage：订单簿冲击和保守缓冲；
- latency_buffer：数据到达、推理和下单期间的价格恶化缓冲。

只有 edge_net 大于策略设定的最小安全边际，才可进入风险层。安全边际不能由 LLM 临时降低。

### 3.2 提前退出

提前退出的回测必须使用当时真实可成交 bid、深度和费用，不能用最后成交价或 midpoint 假设全部成交。

客户端止损只是一项触发规则，不是保证价格。若订单簿不足，模拟必须允许：

- 部分成交；
- 更差价格；
- 完全未成交；
- 市场暂停或结算前无法退出。

### 3.3 二元套利

候选组合的保守净边际：

arb_margin = 1 − VWAP_ask_yes − VWAP_ask_no − fees − slippage − leg_risk_buffer

必须按同一目标数量计算两侧 VWAP。只有以下条件都满足才计为“可执行套利”：

- outcome 映射和结算规则互补；
- 两侧深度足够；
- 费用后边际为正；
- 两腿可原子提交，或单腿暴露在硬限制内；
- 一腿失败时有明确的取消、对冲或停止路径。

没有同时成交的回测记录不得记作套利利润。

### 3.4 做市

做市收益必须拆分为：

- spread capture；
- maker rebate / liquidity reward；
- inventory mark-to-market；
- adverse selection；
- fee、取消失败与链上成本；
- 最终结算损益。

不能只统计成交价差。单边库存和事件跳价必须进入净 P&L。

## 4. 数据规范

### 4.1 数据来源

- Gamma API：市场、事件、规则、结算源、起止时间、token 映射。
- CLOB：订单簿快照/增量、best bid/ask、成交、订单状态。
- Data API：仓位、公开交易、钱包活动。
- 外部数据：新闻、体育赔率、行情和官方事件源。

每条记录至少包含：

- source；
- source_event_id；
- event_time；
- received_time；
- persisted_time；
- schema_version；
- checksum 或去重键。

### 4.2 时间一致性

所有回测必须按 received_time 或当时真实可获得时间重放，禁止使用事后修订内容。必须特别防止：

- 使用市场最终结算结果训练同一事件；
- 使用文章更新时间而非首次发布时间；
- 使用已修订民调、比分或经济数据；
- 使用未来订单簿快照补齐当前深度；
- 将交易观察到的链上时间错误地提前到提交时间。

### 4.3 数据质量阶段门

进入策略回测前必须满足：

- token 与 outcome 映射无歧义；
- 时间戳统一为 UTC 并保留原始时区；
- 订单簿序列号连续，缺口被显式标记；
- 重复成交已去重；
- 市场规则和后续 clarification 均有版本；
- 数据缺失时不做插值成交；
- 未知 fee、tick size、minimum size 或 neg-risk 的交易样本被拒绝，不使用默认猜测。

## 5. 回测设计

### 5.1 数据分割

必须采用按时间向前的分割：

1. 训练集：拟合模型或策略参数；
2. 验证集：选择有限超参数；
3. 冻结样本外测试集：只做一次最终评估；
4. 滚动 walk-forward：模拟定期再训练和真实部署。

禁止随机打乱跨时间样本后声称是样本外结果。高度相关的同一事件、同系列市场和同一新闻催化剂必须放在同一数据分区。

### 5.2 成交模型

最少需要三档模型：

1. **基准档**
   - 按当时订单簿可见深度；
   - 遵守 tick size 和 minimum size；
   - 允许部分成交；
   - 使用当前 fee curve。

2. **保守档**
   - 信号到下单加入实测 P95 延迟；
   - 排队位置不优于新到订单；
   - 滑点至少使用实盘或历史估计的 P75；
   - 数据缺口期间禁止成交。

3. **压力档**
   - 延迟为基准的 2 倍；
   - 滑点为基准的 1.5 倍；
   - 可见深度折减 50%；
   - 注入 WebSocket 断线、订单拒绝和一腿失败；
   - 新闻跳价场景允许完全未成交。

### 5.3 防止过拟合

- 限制可调参数数量并记录全部实验，而非只保留最好结果。
- 对多次试验做 multiple-testing 调整或使用 deflated Sharpe / reality check。
- 记录失败策略，禁止换名后重新选择同一测试集。
- 用 bootstrap 按事件聚类，不能把同一事件中的大量秒级样本当成独立样本。
- 报告参数邻域稳定性；只有一个精确参数点盈利视为脆弱。
- 检查收益是否集中在单一市场、单一事件或极少数异常交易。

## 6. 必须报告的指标

### 6.1 预测质量

- Brier score；
- log loss；
- calibration curve；
- Expected Calibration Error；
- 相对市场隐含概率基线的增量；
- 按类别、概率区间、距结算时间和流动性分层。

### 6.2 交易质量

- 扣除全部费用后的净 P&L；
- 期望收益/笔；
- profit factor；
- 最大回撤及持续时间；
- 波动率和 downside deviation；
- 成交率、部分成交率、拒单率；
- maker/taker 比例；
- 实现滑点与预测滑点误差；
- 从信号到确认成交的 P50/P95/P99 延迟；
- 资金占用时间和年化口径的明确换算。

### 6.3 集中度与尾部风险

- 最大单笔亏损；
- 最差 1%、5% 交易；
- 单市场、单事件、单类别和相关主题暴露；
- 前 1、5、10 笔交易对总利润的贡献；
- 去掉最佳交易后的净收益；
- 结算争议、数据断线和无法退出场景损失。

## 7. 策略专项验证

### 7.1 AI 概率策略

每次预测必须保存：

- 模型供应商、模型名和版本；
- system prompt、模板和参数版本；
- 输入证据 ID 与时间；
- 结构化输出；
- 原始概率和校准后概率；
- 推理完成时间；
- 交易是否实际执行及原因。

阶段门：

- 输出必须通过严格 schema 校验；
- 引用证据可追溯且在预测时已公开；
- 对包含 prompt injection 的市场描述和新闻做红队测试；
- AI 无 signer 和下单工具权限；
- 校准后 Brier score 不劣于未校准结果；
- 样本外净 edge 在费用和压力成交模型下仍为正。

### 7.2 新闻策略

- 至少区分原始来源、转载和聚合摘要。
- 对关键事实要求两条独立来源，或一条权威原始来源。
- 保存首次发布时间和本系统接收时间。
- 检测旧闻重发、讽刺、否认、时间范围和主体同名。
- 先匹配市场完整规则，再判断新闻是否改变结算概率。
- LLM 推理延迟必须计入可交易 edge；若信息已反映到订单簿则放弃追价。

### 7.3 复制交易

源钱包筛选必须使用观察期之后的数据验证，禁止在完整历史上挑选赢家后回测同一历史。

至少评估：

- 源钱包活跃天数和独立事件数；
- 已实现与未实现 P&L；
- 交易规模相对流动性的可复制性；
- 跟随延迟后的实际价格差；
- 是否依赖单个大胜；
- 是否存在相关地址、对冲或转账；
- 开仓和退出均可复制的比例。

阶段门不得只使用 leaderboard win rate。

### 7.4 体育价值策略

- 将博彩公司赔率转换为 no-vig 概率。
- 确认 Polymarket 与外部盘口的结果集合完全一致。
- 对齐加时、延期、取消、比赛完成和数据源规则。
- 区分赛前和滚球；滚球回测加入交易延迟、订单延迟及暂停。
- 发生首发、伤病或比分事件时，按收到消息后的订单簿重放，不能按消息发布时间成交。

### 7.5 临近结算策略

- 解析 resolutionSource、endDate、规则和 edge cases。
- 保存所有 clarification 版本。
- 将争议时间、资金占用和 50/50 等异常结算纳入压力测试。
- 不因价格高于某阈值就认定“确定结算”。
- 未能独立验证权威结果时禁止开仓。

### 7.6 做市策略

- 使用完整订单簿重放和排队模型。
- 模拟撤单在途期间被成交。
- 报告 fill 后 1 秒、10 秒、60 秒的 markout，衡量逆向选择。
- 实施 inventory skew、最大净库存和事件跳价保护。
- 报价数据超过 freshness 阈值立即撤单并停止新报价。
- 奖励只在满足官方评分规则且实际达到最低支付额时计入。

### 7.7 套利策略

- 只使用同一时间点、同一目标数量的两侧 VWAP。
- 记录两腿提交、接受、成交和确认时间。
- 压力测试一腿 live、另一腿 rejected/partial 的场景。
- 对跨平台套利加入桥、账户、规则不一致和结算分叉。
- 只有完成闭环并可复现的交易才计入锁定收益。

## 8. 默认量化阶段门

以下为保守默认值。策略负责人可以收紧；任何放宽都必须通过配置变更、书面理由和人工审批留痕。

### Gate A：静态安全与协议兼容

必须全部通过：

- 使用当前 CLOB V2 SDK/adapter；
- pUSD、deposit wallet、signature type、tick、minimum size、neg-risk、fee 均有集成测试；
- 私钥不出现在仓库、日志、浏览器、Vercel 或数据库表；
- geoblock 检查为 fail closed；
- AI 无执行权限；
- 单元、属性和故障注入测试全部通过；
- 重复事件不能造成重复下单；
- kill switch 能阻止新仓并取消可取消订单。

### Gate B：历史重放

最低样本要求取以下两者中更严格者：

- 一般方向/事件策略：至少 300 个独立决策、60 个活跃交易日；
- 高频、套利或做市：至少 1,000 个可成交机会及 1,000 次模拟 fill；
- 至少覆盖两个明显不同的市场状态。

必须满足：

- 冻结样本外净期望值为正；
- 按事件聚类 bootstrap 的 95% 置信区间下界不小于 0；
- 压力档成交模型下净 P&L 不为负；
- Brier score 不劣于市场概率基线；
- Expected Calibration Error 不高于 0.05，或提供按样本量修正的更严格依据；
- 最大回撤不超过预设研究风险预算；
- 去掉最佳 5 笔交易后仍不为负；
- 任一市场/事件贡献不超过总正收益的 25%，否则需扩大验证样本。

若样本无法满足，不得把“结果不错”替代统计证据；只能标记为实验性策略。

### Gate C：Paper Trading

持续至少 14 个自然日且达到目标策略的最低交易样本。必须：

- 使用实时数据和真实订单约束；
- 不向交易接口提交真实订单；
- 记录假设成交与随后真实可成交价格的偏差；
- 无重复仓位、状态漂移或无法解释的 P&L；
- 数据陈旧、断线和费率未知时均正确停机；
- paper 与回测差异有归因报告。

### Gate D：Shadow Mode

持续至少 7 个自然日：

- 生成完整订单意图并经过所有风控；
- 仅做 dry-run/preview，不签名、不广播；
- 将意图与真实订单簿后续路径比较；
- 预期滑点模型覆盖至少 90% 的观察结果；
- 零次风险边界绕过；
- 重启和网络故障后状态恢复测试通过。

### Gate E：Canary 实盘

只有人工明确启用后才可进入。默认限制：

- 单笔最大风险：净资产的 0.25%，同时受 CANARY_MAX_USD 绝对上限约束；
- 单市场最大开放风险：净资产的 0.5%；
- 全组合最大开放风险：净资产的 2%；
- 单日 realized + unrealized 损失达到 1% 时停止新仓并告警；
- 连续 3 次异常拒单、状态不一致或未解释成交时自动停止；
- 订单金额低于交易所最小值时跳过，不得自动向上取整突破风险上限；
- 初期仅开放一种已验证策略，不同时上线多个新策略。

Canary 至少持续 30 个自然日且完成 100 笔真实关闭交易；低频策略若无法达到样本量，继续维持 canary，不以时间到期自动升级。

### Gate F：有限扩容

扩容必须满足：

- 实盘净 P&L 与回测/纸面预期的差异已解释；
- 实现滑点和延迟未持续突破模型区间；
- 最大回撤未突破 canary 预算；
- 没有未解决的安全、对账和结算事故；
- 真实概率校准未显著恶化；
- 每次风险额度只提高 1.25–1.5 倍；
- 每次提高后重新观察至少 14 天，不允许一步放大到目标资金。

### Gate G：持续运行

即使进入常规运行，也必须：

- 每日 reconciliation；
- 每周策略与数据漂移报告；
- 每月重新做 walk-forward 和费用/滑点压力测试；
- 模型、prompt、数据源、SDK 或合约变化时自动退回 shadow 或 canary；
- Polymarket 协议迁移、费率变化、结算规则变化时重新通过 Gate A。

## 9. 自动停止条件

出现任一条件必须停止新仓；能安全撤销时取消开放订单：

- 市场数据超过 freshness 阈值；
- WebSocket 序列缺口无法补齐；
- CLOB 与本地订单/仓位不一致；
- fee、tick、minimum size 或 neg-risk 未知；
- signer、凭据或密钥疑似泄漏；
- geoblock 返回 blocked 或无法可靠判定；
- 日损失或组合暴露达到上限；
- AI 输出不符合 schema 或证据不可追溯；
- 同一信号产生重复订单；
- 异常成交价格超过最大滑点；
- 协议版本、合约地址或抵押物发生未知变化；
- 人工 kill switch 被触发。

自动停止后不得自动恢复实盘。必须由人工完成原因确认、对账和重新授权。

### 策略

- [ ] 样本外和 walk-forward 报告完成
- [ ] 费用、深度、部分成交、延迟已建模
- [ ] 压力档仍满足 Gate B
- [ ] 收益集中度和尾部风险已报告
- [ ] AI 校准、证据追踪和 injection 测试通过

## 11. 发布报告模板

每个策略版本的发布报告至少包含：

1. 策略 ID、代码提交、模型与 prompt 版本；
2. 数据集快照、时间范围和数据质量；
3. 训练、验证、样本外与 walk-forward 划分；
4. 基准、保守和压力成交模型结果；
5. 预测校准、净收益、回撤、滑点和集中度；
6. 已知失败模式；
7. 通过的阶段门；
8. 当前实盘额度和 kill 条件；
9. 审批人、时间和回滚版本。

对外只允许报告可复现、标明样本和成本口径的历史结果，并附上：

> 历史表现不代表未来结果。自动交易、预测市场、智能合约、流动性、结算和模型均可能造成部分或全部资金损失。
